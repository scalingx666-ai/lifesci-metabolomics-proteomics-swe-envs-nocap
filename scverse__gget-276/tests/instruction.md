# Issue

**Title:** fix(setup): install with uv into the interpreter running gget

## Description

### Problem
`gget setup <module>` runs `uv pip install -U <pkg>` without a target, so uv installs into whatever environment is *activated* (or `./.venv`), not the one gget runs in:
- **No environment activated:** uv fails with `No virtual environment found`. The `python -m pip` fallback then also fails in environments created by `uv venv`, which ship without pip, so setup fails completely. Found while testing the new `gget setup search`.
- **A different environment activated:** uv installs the package there, the import check fails, and gget falls back to pip.

This affects every `gget setup` module, not just `search`.

### Change
- `uv pip install --python sys.executable -U <pkg>`
- `importlib.invalidate_caches()` before the post-install import check

### Tested (wheel built from this branch, Python 3.12, uv-created env without pip)
- not activated: `gget setup search` installs `mysql-connector-python` into gget's env ✅ (fails on main)
- other env activated: installs into gget's env, not the activated one ✅
- `gget.setup("search")` from Python ✅
