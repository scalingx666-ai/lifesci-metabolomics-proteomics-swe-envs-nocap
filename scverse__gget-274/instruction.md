# Issue

**Title:** tests: time out blast tests after 20 minutes

## Description

`test_blast_nt` submits a live search to NCBI web BLAST, and `gget.blast` polls every 61 s until the job is ready. On the Oct 1 run it took **9102 s (2.5 h)** of a 3 h suite, and the py3.12 job hit GitHub's 6 h limit and was cancelled.

### Change
- Add `pytest-timeout>=2.3` to the `test` dependency group
- Mark `tests/test_blast.py` with `pytestmark = pytest.mark.timeout(20 * 60)`, so a backed-up BLAST queue fails that one test instead of stalling the whole job

### Checks
- Confirmed the module-level mark applies to tests generated by the `from_json` metaclass (a sleeping test in that shape fails with `Timeout (>2s)` under a 2 s mark)
- The 6 offline blast error tests pass locally; `test_blast_nt` needs NCBI, so CI is its first real run
- ruff clean
