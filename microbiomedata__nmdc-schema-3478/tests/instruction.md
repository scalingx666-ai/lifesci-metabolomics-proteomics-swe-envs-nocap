# Issue

**Title:** Record elements removed during v11 in deprecated.yaml, with a catalog of all removals

## Description

Part of  (Record past schema removals and renames in deprecated.yaml).

`deprecated.yaml` recorded 32 elements, but the release history shows 679 elements and 1,042 permissible values that were removed or renamed. Without a record, the docs site has no page for an old name, and nothing can search for leftover mentions ().

This PR adds:

- `src/scripts/schema_element_history.py` and `make retired-element-catalog`. They compare the elements defined at each release tag with the current source, find the merge after which each element stopped being defined, and record the PR and commit subjects.
- `assets/schema_element_history/retired_elements.tsv`, the catalog generated by that target.
- 86 `deprecated.yaml` entries for elements last released in v11. Each one cites the PR that removed it. A replacement is recorded only with evidence. For a MIxS enum, the evidence is the slot that used the old enum now pointing at the new one: `exact` when every old permissible value is still there, `possible` when some were dropped. Renames are recorded only when the PR title says rename.

I left out 79 v11 elements whose docs page name would collide with a current element. `linkml generate doc` names enum and type pages in CamelCase, so `arch_struc_enum` and `ArchStrucEnum` both produce `ArchStrucEnum.md`, and the generated page shows only the current enum. Those old spellings stay in the catalog.
